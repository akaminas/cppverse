## What it is

So far every program has run straight down from the first statement of `main` to the last. Models are not like that. A seed germinates *if* the soil is warm enough; a population is declared extinct *if* fewer than one individual remains; a larva pupates *once* it has accumulated enough warmth. The `if` statement lets a program take such decisions: it runs a statement only when a condition is true, and with `else` it can run a different statement when the condition is false.

## Why it matters

Decisions and repetition are the two ingredients that turn a list of calculations into an algorithm. With `if` and the loops of the next lessons you can, in principle, express any computation. In a model, conditionals encode the rules that switch behaviour on and off: thresholds, stage transitions, boundary conditions and checks that the state is still valid.

## How it works in C++

### The if statement

```cpp
if (N < 1.0)
    std::cout << "extinct\n";
```

The keyword `if` is followed by a condition in parentheses and then by one statement. The condition is evaluated; if it is true, the statement runs, otherwise it is skipped. Either way, the program then carries on after the `if`. The parentheses are part of the syntax and cannot be left out.

Conditions are usually comparisons such as `N < 1.0`, `degree_days >= 250.0` or `count == 0` (note the double `==` for "is equal to"). The next lesson, <Concept id="boolean-logic" />, covers comparisons and how to combine them.

### Adding an else

An `else` gives the statement to run when the condition is false. Exactly one of the two branches runs, never both and never neither:

The expected size after one winter is 1.2 × 0.3 × 2.5 = 0.9 individuals, so the first branch runs. Change the starting size to 2.0 and the second branch runs instead.

### Blocks: several statements per branch

A branch is a single statement, but that statement may be a *compound statement* (a block): any number of statements wrapped in braces. The braces in the example above are blocks with one statement each. Blocks matter as soon as a branch must do two things:

```cpp
if (N < 1.0) {
    N = 0.0;                       // set the population to exactly zero
    std::cout << "extinct\n";      // and report it
}
```

Without the braces only the first statement would belong to the `if`; the second would run every time, whatever its indentation suggests. This site always uses braces, even around a single statement, so that adding a line later cannot silently change the logic.

A block is also a scope (see <Concept id="scope" />): a variable declared inside a branch exists only until that branch's closing brace.

```cpp
if (N >= 1.0) {
    const double surplus = N - 1.0;   // exists only inside this block
    std::cout << surplus << '\n';
}
// surplus is not visible here
```

### Chains of alternatives: else if

When there are more than two possibilities, put another `if` after the `else`. The conditions are tested from the top, and the first one that is true wins; its branch runs and the rest of the chain is skipped. A final plain `else` catches everything that matched none of the tests.

<Example file="foundations/conditionals_stage.cpp" mark="16-24" />

Because the tests run in order, each later branch can assume that the earlier conditions were false. The pupa branch does not need to say "at least 250 *and below 400*": it is reached only when the adult test has already failed. This is also why the order matters. If `degree_days >= 100.0` came first, every individual past 100 degree-days would be called a larva, adults included.

`else if` is not a separate keyword. It is an `else` whose single statement happens to be another `if`. Written out with braces, the same chain is a nest of ifs inside elses, which is why the flat layout above is easier to read.

### Nesting, and which if an else belongs to

An `if` can sit inside a branch of another `if`. That is fine, but it creates a trap known as the *dangling else*:

```cpp
// Intended: report "too cold" when the temperature is not above the threshold
if (temperature > base)
    if (degree_days > 400.0)
        std::cout << "adult\n";
else
    std::cout << "too cold to develop\n";
```

The indentation suggests that the `else` belongs to the first `if`. The compiler ignores indentation: an `else` always pairs with the nearest preceding `if` in the same block that does not yet have one, here the inner `if`. The program therefore prints "too cold to develop" on a warm day before the degree-day threshold is reached, and nothing at all on a cold day. Braces fix the pairing:

```cpp
if (temperature > base) {
    if (degree_days > 400.0) {
        std::cout << "adult\n";
    }
} else {
    std::cout << "too cold to develop\n";
}
```

With `-Wall`, GCC and Clang warn about the unbraced version ("suggest explicit braces to avoid ambiguous else"). Treat the warning as an error, as this site's programs do.

<Callout kind="tip" title="Indentation">
The compiler does not care how you indent, but readers do. Indent each branch one level deeper than its `if`, keep the style consistent, and let your editor do it for you. With nested conditions, consistent indentation makes a misplaced brace stand out at once.
</Callout>

<Callout kind="modern" title="if with an initialiser (C++17)">
Since C++17 an `if` may declare a variable just for itself: `if (const double next = lambda * N; next < 1.0) { … }`. The variable `next` is visible in the condition and in both branches, and nowhere else. It is handy for keeping a temporary result out of the surrounding scope.
</Callout>

## In biological modelling

Conditionals are where a model's rules live. Some common patterns:

- **Extinction and quasi-extinction.** A deterministic model can produce 0.3 individuals. Many models treat a population below one individual (or below a small quasi-extinction threshold) as extinct: `if (N < 1.0) { N = 0.0; }`.
- **Thresholds and switches.** Germination when soil temperature exceeds a minimum, migration when day length passes a critical value, a harvest only when the stock is above a reference level.
- **Stage transitions.** An individual moves from egg to larva to pupa once its accumulated degree-days pass each threshold, an else-if chain like the one above.
- **Validity checks.** Before running a simulation, check that the parameters make sense, for example that a survival probability lies between 0 and 1, and stop with a message if not.
- **Events in stochastic models.** In a stochastic simulation the program first draws which event happens and then applies its effect with a conditional. The <Concept id="gillespie" /> lesson does exactly that.

Keep the conditions close to the language of the model description. If the paper says "individuals mature at 250 degree-days", the code should say `degree_days >= 250.0`, with the 250 stored in a named constant that the reader can check.

## Common mistakes

- **A semicolon too many.** `if (condition);` controls an empty statement; the block that follows always runs. See the second check above.
- **Missing braces.** Two statements indented under an `if` without braces: only the first is conditional.
- **The dangling else.** An `else` pairs with the nearest unmatched `if`, not with the one its indentation suggests. Use braces whenever ifs are nested.
- **Chains in the wrong order.** In an else-if chain only the first true condition counts. Order threshold tests so that the most demanding comes first, or reverse the comparisons.
- **`=` instead of `==`.** `if (count = 0)` assigns zero and then tests it, so it is always false. The compiler warns about it; <Concept id="boolean-logic" /> explains why it compiles at all.
- **Comparing computed doubles for exact equality.** `if (N == 0.3)` is rarely what you want after arithmetic; compare with a tolerance (see <Concept id="boolean-logic" />).
