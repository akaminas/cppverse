## What it is

Many organisms reproduce in a single season each year: annual plants, univoltine insects, salmon, temperate songbirds. For such populations it is natural to count individuals once per generation, at the same point of the life cycle, and to ask how this year's count determines next year's. A *discrete-time model* answers with a rule of the form

$$
N_{t+1} = f(N_t),
$$

where $N_t$ is the population size at the census of generation $t$ ($t = 0, 1, 2, \dots$, a whole number) and $f$ summarises everything that happens between two censuses: reproduction, mortality, competition. An equation that gives the next value from the current one is called a *recurrence* or *difference equation*.

The recurrence **is** the model. It is not an approximation of a continuous-time model with a step size of one generation, and there is nothing to make more accurate by taking smaller steps: the model only claims to describe the population at the census. This is different from numerical integration of a differential equation (see <Concept id="odes" />), where a step size is a property of the approximation and not of the biology.

## Why it matters

A discrete-time model is the smallest complete simulation. It has a state that changes, a rule that changes it, and a loop that applies the rule repeatedly, and every model in this atlas is built from the same three parts. In a matrix model the state is a vector of stages; in an individual-based model it is a collection of individuals; in a stochastic model the rule draws random numbers. If you can write, check and interpret the program in this lesson, you can follow every later one.

## How it works in C++

### From a hypothesis to an equation

Start with a hypothesis about the biology. When a population is sparse, each individual leaves on average $R_0$ offspring that survive to the next census. As density rises, individuals compete for food or nest sites, and the number of offspring per individual falls. Competition is *compensatory*: more parents never produce fewer offspring in total; the total levels off at high density.

A simple equation with exactly these properties was proposed for fish stocks by Beverton and Holt:

$$
N_{t+1} = \frac{R_0\,N_t}{1 + N_t/M}.
$$

- $N_t$: population size in generation $t$ (individuals, or individuals per unit area).
- $R_0$: number of surviving offspring per individual at very low density, per generation (dimensionless, $R_0 > 0$).
- $M$: the density at which the number of offspring per individual is halved (same units as $N$, $M > 0$).

The per-capita growth factor is $R_0 / (1 + N_t/M)$. It equals $R_0$ when $N_t$ is near zero, $R_0/2$ when $N_t = M$, and keeps falling as $N_t$ grows, while the total $N_{t+1}$ approaches $R_0 M$ but never exceeds it. If $R_0 > 1$, the population settles at the equilibrium where the growth factor is exactly 1:

$$
\frac{R_0}{1 + K/M} = 1 \quad\Longrightarrow\quad K = (R_0 - 1)\,M.
$$

If $R_0 \le 1$, even a sparse population fails to replace itself and declines to zero.

### State, parameters and initial conditions

Before writing code, sort every quantity in the model into one of three roles:

| Role | Meaning | In this model |
|---|---|---|
| **State variable** | What changes over time and must be remembered from one step to the next | $N_t$ |
| **Parameter** | Fixed during a run; describes the biology or the environment | $R_0$, $M$ |
| **Initial condition** | The value of the state at $t = 0$ | $N_0$ |

The number of generations to simulate, $T$, is a setting of the experiment rather than part of the biology.

The test for a state variable is: *do I need to know this to compute the next generation, and does it change?* If next year's population depended on last year's as well, or on the age of each individual, those quantities would be part of the state too, and the state would become a vector (see <Concept id="matrix-models" />).

### The update rule

The line `N = R0 * N / (1.0 + N / M);` is the model. In a program that will grow, it deserves a name of its own. An *update rule* is a function that takes the current state and the parameters and returns the next state:

<Example file="algorithms/beverton_holt.cpp" mark="14-24" />

Lines 14–19 gather the parameters in a <Concept id="structs">struct</Concept> with default values, so that they travel together and the function signature stays short. Lines 21–24 are the update rule. It is a direct transcription of the equation, it changes nothing outside itself, and it returns the new state. That has practical consequences:

- **You can test it alone.** With $N = M$ the growth factor must be $R_0/2$, so `nextGeneration(40.0, p)` must return $2.2 \times 40 / 2 = 44$.
- **You can check it against the paper.** The equation lives in exactly one place.
- **You can replace it.** A different hypothesis about density dependence means a different function, and the rest of the program stays as it is.

The state is passed by value (a `double` is cheap to copy) and the parameters by `const&` (see <Concept id="const-reference" />). The parentheses in `(1.0 + N / p.M)` matter: without them, C++ would divide by 1 and then add `N / p.M`.

### The simulation loop

The rule is applied repeatedly in `simulate` (lines 26–37). In pseudocode:

```text
N ← N0
store N
for t ← 0 to T − 1 do
    N ← nextGeneration(N)
    store N
```

Each pass of the `for` loop is one generation (see <Concept id="for-loop" />). The trajectory is kept in a `std::vector<double>` (see <Concept id="std-vector" />): `push_back` appends one state per generation, so after $T$ generations the vector holds the $T + 1$ states $N_0, N_1, \dots, N_T$. `reserve` (line 29) only tells the vector how much room to set aside; it does not change its contents.

Storing the whole trajectory, rather than printing as you go, separates *running* the model from *analysing* it. The finished trajectory can be scanned for its peak, compared with a closed form, or written to a file (see <Concept id="trajectory-output" />). `main` does exactly that: it reads optional parameters from the command line (lines 41–44, see <Concept id="command-line" />), refuses impossible values (lines 46–49), runs the simulation and prints a CSV table. With the default parameters the output begins

```text
generation,N
0,5
1,9.77777777778
2,17.2857142857
3,26.5536159601
```

and, by generation 30, reads `47.999999978`: the population has all but reached $K = (2.2 - 1) \times 40 = 48$.

### Verification against the exact solution

Before trusting a simulation, compare it with something known independently. For the Beverton–Holt model, the substitution $x_t = 1/N_t$ turns the recurrence into a linear one, $x_{t+1} = x_t / R_0 + 1/(R_0 M)$, which can be solved by hand. For $R_0 \ne 1$ the result is

$$
N_t = \frac{K\,N_0}{N_0 + (K - N_0)\,R_0^{-t}}, \qquad K = (R_0 - 1)\,M.
$$

The simulation and the formula agree to within rounding error:

<Figure id="bh-verification" />

Agreement here does not prove the program correct for every model you will write, but it does show that the update rule, the loop and the storage work together as intended. That is worth knowing before you change the rule to one without a closed form.

### Qualitative behaviour

Whatever the starting size, a Beverton–Holt population approaches its equilibrium smoothly, without overshooting, or declines to zero if $R_0 < 1$:

<Figure id="bh-trajectories" />

The smooth approach is a consequence of compensation: because $N_{t+1}$ increases with $N_t$, a population below $K$ can never jump above it. Change the hypothesis, and the dynamics change. If crowding is so severe that a dense population produces *fewer* offspring than a moderate one (overcompensation), the rule becomes hump-shaped. The best-known example is the discrete logistic map, $x_{t+1} = r\,x_t\,(1 - x_t)$, where $x_t$ is density scaled so that $x = 1$ means no offspring survive, and $r$ (dimensionless) is the maximum growth factor. With the same loop and a different update rule, it settles to a steady state, alternates in a two-generation cycle, or fluctuates without ever repeating:

<Figure id="logistic-map-regimes" />

May (1976) used this example to show that very simple deterministic models can produce apparently random fluctuations. For a modeller, the lesson is practical: the long-run behaviour of a discrete-time model depends on the shape of its update rule, so look at trajectories before reporting an equilibrium.

## In biological modelling

A discrete-time model fits populations that breed in distinct seasons with little overlap between generations, censused at the same point of each cycle. It fits less well when reproduction and death go on all the time, as in many microbes or in humans, where a differential equation is the natural description. The census point is part of the model: counting before breeding or after breeding changes what $N_t$ and $R_0$ mean, and therefore how they are estimated from data.

The program structure carries over to every later model:

- a **state** (here one number; later a vector of stages or a list of individuals);
- **parameters**, gathered in a struct and treated as `const`;
- an **update rule**, one function that maps the state at $t$ to the state at $t+1$;
- a **loop** that applies the rule and stores the trajectory;
- **output** of the trajectory for analysis, separate from the simulation.

Keep verification in the workflow from the start. A closed-form solution exists here; in models without one, check the equilibrium, a special case ($R_0 = 1$ gives $N_t = N_0 / (1 + N_0 t / M)$), or conservation laws. The lesson on <Concept id="verification" /> develops this.

## Common mistakes

- **Storing a density in an `int`.** `int N` truncates every generation, and `N / M` with two integers is integer division. Both run without complaint and give wrong trajectories (see <Concept id="integer-division" />).
- **Changing a parameter inside the loop.** If $R_0$ is modified by accident, every later generation uses the wrong model. Declare parameters `const` and let the compiler guard them.
- **Off-by-one runs.** $T$ generations give $T + 1$ states. Decide whether the loop counts generations simulated or states stored, and test it with $T = 0$ and $T = 1$.
- **Missing parentheses.** `R0 * N / 1.0 + N / M` is $(R_0 N / 1) + N/M$, a different model that grows without bound.
- **Overwriting the state too early.** With one state variable this cannot happen; with two or more, updating one before the other has used its old value changes the model. See <Concept id="update-order" />.
- **Reporting an equilibrium from one short run.** Look at the whole trajectory: a slowly approached equilibrium, a cycle and chaos can look alike over a few generations.

<details>
<summary>Worked answer for exercise 2</summary>

Add a function for the closed form and compare inside the output loop:

```cpp
double exactSolution(double t, const Parameters& p) {
    if (p.R0 == 1.0) return p.N0 / (1.0 + p.N0 * t / p.M);
    const double K = (p.R0 - 1.0) * p.M;
    return K * p.N0 / (p.N0 + (K - p.N0) * std::pow(p.R0, -t));
}
```

Track `std::max(worst, std::abs(N[t] - exactSolution(t, p)))` over all generations. With the defaults the largest difference is about $10^{-14}$ individuals, which is rounding error in the last bits of a `double`. Comparing `p.R0 == 1.0` exactly is acceptable here because the value is either typed as 1 or not; it would not be for a computed value.
</details>

<details>
<summary>Worked answer for exercise 3</summary>
Harvesting multiplies $R_0$ by $(1 - h)$, so the equilibrium becomes $K_h = [(1 - h)R_0 - 1]\,M$. The population persists only if $(1 - h) R_0 > 1$, that is $h < 1 - 1/R_0$. For $R_0 = 2.2$ this is $h < 0.545$; with $h = 0.3$ the equilibrium is $(0.7 \times 2.2 - 1) \times 40 = 21.6$. A simulation with $h = 0.6$ declines towards zero.
