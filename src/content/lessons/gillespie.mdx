## What it is

Many biological processes are made of discrete events that happen at random moments: an individual is born or dies, a host is infected or recovers, a molecule of mRNA is transcribed or degraded, a patch is colonised or goes extinct. Each kind of event happens at a rate that depends on the current state of the system: the more individuals, the more births per year.

**Gillespie's direct method**, also called the stochastic simulation algorithm, simulates such a process exactly. It does not advance time in fixed steps. It asks two questions, again and again: *when* does the next event happen, and *which* event is it? Then it jumps straight to that moment, applies that event, and asks again. Daniel Gillespie published the method in 1976 for chemical reactions in a well-mixed solution; the same mathematics describes populations, epidemics and gene expression.

## Why it matters

- **Individuals are whole.** The state is a set of counts, so populations can reach exactly zero and stay there. Extinction, fade-out of an epidemic and loss of a gene product are possible outcomes, not artefacts of rounding.
- **Time is continuous.** There is no time step to choose, and no question of what happens when two events fall in the same step.
- **It is exact.** Each simulated path is a draw from precisely the probability distribution that the model defines. Time-stepped approximations are only correct in the limit of a vanishing step.
- **It connects to deterministic models.** The rates of a Gillespie model are the terms of an ODE model. For large populations the stochastic paths approach the ODE solution, which <Concept id="replicates" /> examines.

## How it works in C++

<Anchor id="propensities" />

### Events and propensities

A Gillespie model is a list of events. Each event $j$ has

- a **state change** $\nu_j$: what it adds to or removes from each count, and
- a **propensity** $a_j(x)$: its rate in the current state $x$, in events per unit time. For a short interval $dt$, $a_j(x)\,dt$ is the probability that event $j$ happens during that interval.

The **linear birth–death process** has one count, the population size $N$. Each individual gives birth at rate $b$ and dies at rate $d$, both per individual per year:

| Event | Reaction | State change | Propensity |
|---|---|---|---|
| birth | $X \xrightarrow{\;b\;} 2X$ | $N \to N + 1$ | $a_1 = b\,N$ |
| death | $X \xrightarrow{\;d\;} \varnothing$ | $N \to N - 1$ | $a_2 = d\,N$ |

The **SIR epidemic** in a closed population of $N$ hosts has three counts: susceptible $S$, infectious $I$ and recovered $R$, with $S + I + R = N$:

| Event | Reaction | State change | Propensity |
|---|---|---|---|
| infection | $S + I \xrightarrow{\;\beta\;} 2I$ | $(S, I, R) \to (S - 1, I + 1, R)$ | $a_1 = \beta\, S I / N$ |
| recovery | $I \xrightarrow{\;\gamma\;} R$ | $(S, I, R) \to (S, I - 1, R + 1)$ | $a_2 = \gamma\, I$ |

Here $\beta$ is the transmission rate per day: each infectious host makes potentially infectious contacts at rate $\beta$, and a fraction $S/N$ of those contacts are with susceptible hosts. $\gamma$ is the recovery rate per day, so the mean infectious period is $1/\gamma$ days.

The **total propensity** is the rate at which *anything* happens:

$$
a_0(x) = \sum_j a_j(x).
$$

Writing down the events and their propensities *is* the modelling. Propensities proportional to a single count, like $bN$ and $\gamma I$, describe individuals acting independently; products such as $SI$ describe interactions. A propensity must be zero whenever its event is impossible: $dN$ is zero when $N = 0$, and $\beta SI/N$ is zero when either $S$ or $I$ is zero, so no count can ever become negative.

<Anchor id="waiting-times" />

### Waiting times are exponential

Suppose the state does not change. Then each event $j$ behaves like an alarm clock that rings after a random time $T_j$, exponentially distributed with rate $a_j$:

$$
P(T_j > s) = e^{-a_j s}.
$$

The clocks run independently, and the next event is the one whose clock rings first. Nothing has happened by time $s$ only if no clock has rung, so the waiting time $\tau = \min_j T_j$ satisfies

$$
P(\tau > s) = \prod_j e^{-a_j s} = e^{-a_0 s}.
$$

The waiting time to the next event is therefore **exponential with the total propensity as its rate**, with mean $1/a_0$. The more that can happen, the sooner something does. The probability that event $j$ is the one that rings first is

$$
P(\text{event } j \text{ first}) = \int_0^\infty a_j e^{-a_j s} \prod_{k \ne j} e^{-a_k s}\, ds = \int_0^\infty a_j e^{-a_0 s}\, ds = \frac{a_j}{a_0},
$$

a weighted lottery with the propensities as weights (<Concept id="weighted-lottery" />). Both results use the same clocks, and the choice of event turns out to be independent of the waiting time.

After the event the state changes, and so do the propensities. Why may we throw away the clocks that did not ring and start new ones? Because exponential clocks have **no memory**:

$$
P(T > s + u \mid T > s) = \frac{e^{-a(s + u)}}{e^{-a s}} = e^{-a u} = P(T > u).
$$

A clock that has already run for a time $s$ without ringing is, statistically, as good as new. So at every moment, the future of the process depends only on the current state. That is what makes the simulation exact, and it means the program never needs to remember how long ago anything happened.

The waiting time is drawn with `std::exponential_distribution<double>(a0)`, whose parameter is the **rate** (<Concept id="random-library" />). The library does the equivalent of inversion: if $u$ is uniform on $(0, 1]$, then $\tau = -\ln(u) / a_0$ is exponential with rate $a_0$. The figure checks the simulator's waiting times against $e^{-a_0 s}$.

### The direct method

Put together, one run of the direct method from state $x$ at time $t$ to an end time $T$ is:

1. Compute every propensity $a_j(x)$ and their sum $a_0$.
2. If $a_0 = 0$, no event can ever happen: the process is in an **absorbing state**. Stop.
3. Draw the waiting time $\tau \sim \text{Exponential}(a_0)$.
4. If $t + \tau > T$, the next event falls after the end of the simulation. Stop **without** applying it.
5. Choose event $j$ with probability $a_j / a_0$.
6. Set $t \leftarrow t + \tau$ and $x \leftarrow x + \nu_j$. Return to step 1.

Only steps 1 and 6 depend on the model: the propensities and the state changes. Everything else is the same for every model, which is why the algorithm is usually written once and reused.

### Stopping correctly

**At the end time.** The state at time $T$ is the state after the last event *before* $T$. An event drawn for $t + \tau > T$ has not happened yet at $T$. Applying it anyway records, as the state at $T$, the state at some later time. The error is at most one event per run, but it is systematic: when $b > d$ the extra event is more often a birth than a death, so the recorded population sizes are biased upwards on average.

**In an absorbing state.** When $N = 0$ in the birth–death process, or $I = 0$ in the epidemic, every propensity is zero and nothing can ever happen again. That is extinction, or the end of the epidemic: a normal, often the most important, outcome. Stop the run and record it. Test $a_0$ *before* drawing a waiting time, because `std::exponential_distribution` requires a positive rate; a rate of zero violates its precondition. A zero total propensity is an error only in a model where it cannot legitimately occur, and there throwing an exception (<Concept id="exceptions" />) is the right response.

<Callout kind="manual" title="Two differences from the course manual">
The manual's Gillespie program loops `while (t < tEnd)` and advances the time before applying each event, so the last event of a run, which falls after `tEnd`, is still applied. It also throws an exception when the total rate is zero. For the models here that state is extinction or the end of an epidemic, a result to be recorded rather than an error, so this site stops the run instead.
</Callout>

### Why no time step is needed

A common alternative divides time into steps of length $dt$ and lets a birth happen with probability $bN\,dt$ in each step. That is an approximation: it allows at most one event per step, treats the rates as constant during the step, and is accurate only when $a_0\,dt$ is much smaller than 1. The direct method has no $dt$. Between events nothing changes, so it jumps directly from one event to the next, and its paths have exactly the distribution defined by the propensities. "Exact" here means exact *for the model*, given good random numbers; whether the model describes the biology is a separate question.

## In biological modelling

### A stochastic SIR epidemic

The program below simulates an epidemic in 500 hosts with $\beta = 0.3$ and $\gamma = 0.1$ per day (a basic reproduction number $R_0 = \beta/\gamma = 3$), starting with 5 infectious hosts. It uses `std::discrete_distribution` for the choice between infection and recovery and a `switch` to apply the chosen state change (<Concept id="switch" />). Recording on a grid uses the memorylessness once more. Before every save time, the inner loop applies all events that happen before it. When the next event would fall after the save time, it is not applied: the clock is set to the save time, and a fresh waiting time is drawn from there. The time already waited has no influence on the time still to wait, so this changes nothing about the process. Once $I = 0$, the epidemic is over and every remaining save time records the final state.

Run the program with a few seeds. Almost every run produces a large outbreak that has infected most hosts by about day 80, but the timing and the final number infected vary. Now change the start to a single infectious host (`Hosts x{N - 1, 1, 0}`). About one run in three now fizzles out after a handful of infections, because the first infectious hosts recover before passing the infection on; for an epidemic started by $I_0$ hosts this happens with probability close to $(\gamma/\beta)^{I_0}$, which is only about 1 in 250 for $I_0 = 5$. Estimating such probabilities needs many runs, the subject of <Concept id="replicates" />.

### A template for any model

For more than two or three events, keep the model-specific parts in data: a function that returns the vector of propensities, and a table of state changes. The loop itself does not change:

```cpp
// Model-specific: a_j(x) for every event j, and the change ν_j of each event.
std::vector<double> propensities(const std::vector<int>& x);
const std::vector<std::vector<int>> change{{-1, +1, 0}, {0, -1, +1}};

// The direct method from time t to endTime.
while (true) {
    const std::vector<double> a = propensities(x);
    double a0 = 0.0;
    for (const double aj : a) a0 += aj;
    if (a0 <= 0.0) break;                          // absorbing state
    std::exponential_distribution<double> waiting(a0);
    const double tau = waiting(rng);
    if (t + tau > endTime) break;                  // the next event is too late
    t += tau;
    std::discrete_distribution<std::size_t> which(a.begin(), a.end());
    const std::size_t j = which(rng);
    for (std::size_t k = 0; k < x.size(); ++k) x[k] += change[j][k];
}
```

The site's own laboratory uses exactly this structure (`src/lib/simulations/gillespie.ts`). Both distributions are rebuilt for every event because the propensities change; for a handful of events that costs little. If you prefer a `switch` over the event index, as in `sir_gillespie.cpp`, give it a `default:` branch that throws `std::logic_error` (from `<stdexcept>`) once the model has more events than two: an index that no `case` handles is a programming error and should not pass silently.

### Assumptions and costs

- **Well mixed and memoryless.** Every individual of a type is equivalent, and the rates depend only on the current counts. As a consequence, durations such as the infectious period are exponentially distributed. Real infectious periods are usually less variable; adding stages ($I_1 \to I_2 \to R$) is a standard remedy.
- **Run time grows with the number of events.** The expected number of events per unit time is $a_0$, which grows with population size. Millions of events are fast, but a population of $10^7$ simulated for years may not be. Approximate methods such as tau-leaping trade exactness for speed, and the next-reaction method of Gibson and Bruck is faster when there are many event types.

## Common mistakes

- **Using the mean as the parameter.** `std::exponential_distribution<double>(1.0 / a0)` draws waiting times with mean $a_0$, not $1/a_0$. Pass the rate, `a0`.
- **Applying the event after the end time.** Check $t + \tau > T$ before changing the state.
- **Drawing with a total propensity of zero.** Test $a_0 > 0$ first and treat $a_0 = 0$ as the absorbing state it is.
- **Stale propensities.** Recompute every propensity after every event; a rate computed from an old state belongs to a different process.
- **Integer arithmetic in a propensity.** With `int` counts, `beta * (S * I / N)` divides integers first and truncates, and for large populations `S * I` can overflow `int`, which is undefined behaviour. Write `beta * S * I / N`, which is evaluated left to right in `double` from the first multiplication.
- **Plotting events as straight lines.** Between events the state is constant. Draw a path as steps, or record it on a time grid as `sir_gillespie.cpp` does.

<summary>Worked answer to exercise 1</summary>

Transcription has a constant propensity, so $a_0 = k + \delta m$ is never zero and there is no absorbing state. The core of the loop is

```cpp
const double transcription = k;
const double degradation = delta * m;
const double total = transcription + degradation;
std::exponential_distribution<double> waiting(total);
const double tau = waiting(rng);
if (t + tau > saveTime) { t = saveTime; break; }
t += tau;
if (uniform(rng) * total < transcription) ++m;
else --m;
```

inside a loop over save times as in `sir_gillespie.cpp`. The mean and the variance should both be close to $k/\delta = 20$ molecules. Samples one minute apart are correlated (a molecule lives for 10 minutes on average), so the estimates scatter more than 300 independent samples would.
