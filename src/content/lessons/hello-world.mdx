## What it is

A C++ program is a text file of instructions that a compiler translates into something your computer can run. Every program, from a six-line greeting to a simulation of a million individuals, shares the same skeleton. Here is the smallest one that does something visible:

<Example file="foundations/hello.cpp" />

It prints `Hello, world!` and stops. The program is trivial on purpose: with the arithmetic and the model taken away, only the skeleton is left to look at.

## Why it matters

Programming languages are strict. C++ will not guess what you meant: a missing semicolon or a misspelt name stops the build. That strictness is useful in science. A program does exactly what it says, so once you can read every symbol in it you can check it against the model you intended.

This lesson therefore takes nothing for granted. Each element of the program gets a name and a purpose. Later lessons will add variables, decisions, loops and functions, but they all sit inside this skeleton.

## How it works in C++

Select any element of the program below to see its role. The arrow keys step through them in order.

<Anatomy id="hello" />

Read top to bottom, the program says:

1. **`#include <iostream>`**: before compiling, paste in the declarations of the standard input/output library. This is how the compiler learns what `std::cout` is.
2. **`int main() { … }`**: define the function `main`, where every C++ program starts. It takes no parameters, `()`, and returns an `int` to the operating system. The braces enclose its body.
3. **`std::cout << "Hello, world!\n";`**: send the text between the quotes, followed by a newline, to the console.
4. **`return 0;`**: end `main` and report success (zero) to the operating system.

<Anchor id="namespaces" />

### Namespaces and `std::`

Large programs and libraries define thousands of names. A *namespace* groups names so that they cannot collide. The whole C++ standard library lives in the namespace `std`, and the scope-resolution operator `::` reaches into it: `std::cout` is "the `cout` that belongs to `std`".

You will often see programs that write `using namespace std;` once and then use `cout` without the prefix. That works, but it imports hundreds of names into your program at once, and some of them (`count`, `distance`, `size`) are names you will want for your own variables. This site keeps the `std::` prefix everywhere, which also makes clear at a glance which names come from the library.

### Printing text and values

`std::cout` is an *output stream*: whatever you insert into it with `<<` is converted to text and written to the console. You can chain insertions, and you can print numbers, including the results of calculations:

<Example file="foundations/hello_population.cpp" mark="8-11" />

A few details are worth noticing:

- `'\n'` (single quotes) is a single newline *character*; `"\n"` (double quotes) is a *string* containing one newline. Both print a line break.
- `120 + 45` is evaluated before it is printed, so the program prints `165`, not the text `120 + 45`. Text you want to appear literally goes inside quotes.
- Spaces inside quotes are printed exactly. Spaces outside quotes only make the code easier to read.

<Callout kind="modern" title="std::endl and '\n'">
Many older programs end lines with `std::endl`. It prints a newline *and* flushes the output buffer, forcing the text to be written immediately. In a simulation that prints thousands of lines, repeated flushing can make output noticeably slower. Use `'\n'` and flush only when you need to (for example `std::cout << std::flush;` before a long computation).
</Callout>

## In biological modelling

Every simulation in this atlas, whether a matrix population model, an ODE integrator or an individual-based model, is built on this skeleton. `main` will grow into a short, readable outline of the experiment:

```cpp
int main() {
    // 1. set parameters and the initial state
    // 2. run the model forward in time
    // 3. write the trajectory to a file
    return 0;
}
```

`std::cout` is also your first debugging and inspection tool. Printing the state of a model at a few time points is the quickest way to see whether a simulation is doing what you intended, long before you make polished figures.

## Common mistakes

<Callout kind="pitfall" title="A forgotten semicolon">
The compiler reports the error where it *noticed* the problem, which is often the line after the missing semicolon. For the program below, GCC says something like `error: expected ';' before 'return'`, pointing at line 10 although the semicolon is missing at the end of line 9.
</Callout>

<Example file="foundations/missing_semicolon.cpp" mark="9" editable={true} />

Other first errors to recognise:

- **Wrong case.** C++ is case-sensitive: `Main`, `STD::cout` and `std::Cout` are all different names from `main` and `std::cout`.
- **Curly quotes.** Code pasted from a word processor may contain “typographic quotes”, which the compiler does not accept as string delimiters. Use the plain `"` key.
- **Unbalanced braces.** Every `{` needs a matching `}`. Consistent indentation makes a missing brace easy to spot.
- **Building with `gcc` instead of `g++`.** `gcc` compiles C++ source but does not link the C++ standard library by default, so the program fails at the link step with errors about undefined references to `std::cout`. See <Concept id="compilation" />.
