## What it is

C++ is revised every three years. C++20 was the largest revision since C++11, and C++23 added a further set of conveniences. The examples in this atlas are written for C++23 and compiled with `-std=c++23`, so the C++20 and C++23 features described here are the baseline, not extras. This lesson covers the ones that most improve model code, shows each briefly, and says which compilers support it. The last section lists what C++26 adds.

To use these features, compile with `-std=c++23` (GCC, Clang) or `/std:c++latest` (Visual Studio). The C++20 features also work with `-std=c++20`. Two related features still depend on build-tool support and are not used on this site: C++20 *modules* and, from C++23, `import std;`. Whether they work depends on your compiler, your build system and its version. Features from C++26 carry the badge <Std v="c++26" /> and need a very recent compiler.

## Why it matters

Each feature below removes a class of mistakes or a piece of boilerplate that models are prone to: passing the wrong length with a pointer, mismatched format codes in output, cryptic template errors, positional parameter lists in which two doubles are swapped. None of them changes what a model computes.

The cost is portability. A university cluster may provide a compiler several years old, and a collaborator may use a different platform. Before relying on a feature, check that every place where the model must run supports it.

### `std::span`: a view of contiguous values

A function that reads a sequence of doubles usually takes `const std::vector<double>&`. That works only for vectors, and only for whole vectors. A `std::span<const double>` accepts any contiguous sequence (a vector, a `std::array`, part of either) without copying:

```cpp
double mean(std::span<const double> values);

mean(trajectory);                      // a whole vector
mean(std::span{trajectory}.last(10));  // its last 10 values
mean(monthlyRainfall);                 // a std::array<double, 12>
```

A span is two numbers, a pointer and a length, so it is passed by value. It owns nothing: like a reference, it dangles if the underlying vector is destroyed or reallocated while the span is in use. Use spans as function parameters, not as long-lived members.

### Ranges and views

The `std::ranges` versions of the standard algorithms take a whole container instead of a pair of iterators, and they accept a *projection*, a member or function to compare by:

```cpp
std::ranges::sort(population, {}, &Individual::massGrams);   // sort by mass
const auto oldest = std::ranges::max_element(population, {}, &Individual::ageYears);
```

*Views* are lazy, composable transformations of a range. Nothing is copied or computed until the view is iterated:

```cpp
// Per-capita growth rates of a trajectory, only where the population exceeds 10.
auto growth = std::views::iota(std::size_t{1}, N.size())
            | std::views::filter([&](std::size_t t) { return N[t - 1] > 10.0; })
            | std::views::transform([&](std::size_t t) { return N[t] / N[t - 1]; });
for (const double lambda : growth) std::cout << lambda << '\n';
```

C++23 adds more views, among them `std::views::zip` (walk several ranges together), `std::views::chunk` (blocks of fixed length) and `std::views::slide` (overlapping windows of fixed length, such as consecutive pairs of a trajectory), and `std::ranges::to`, which collects a view into a container. Views are useful but have sharp edges: they refer to the data they view, so they must not outlive it; some views, such as `filter`, cannot be iterated through a `const` reference; and compiler errors in long pipelines are hard to read. For a simple loop, a plain range-based `for` (see <Concept id="auto-range-for" />) is often clearer.

### `std::format` and `std::print`

`std::format` builds a string from a *format string* with replacement fields `{}` and a list of arguments, much like Python's f-strings:

```cpp
std::cout << std::format("{:>4} {:>8.2f}\n", year, N);
```

The format string is checked at compile time, the result is independent of any stream state (no forgotten `std::fixed` affecting later lines), and the rounding is exact and identical on every platform, which makes output files reproducible (see <Concept id="output-formatting" />). C++23 adds `std::print`, which formats and writes in one step:

```cpp
#include <print>                                   // C++23
std::print("{:>4} {:>8.2f}\n", year, N);           // to standard output
std::println(file, "{},{:.6g}", t, N);             // to a FILE*, with a newline
```

On a compiler without `<format>`, the open-source `{fmt}` library offers the same interface for C++11 and later; `std::format` was standardised from it.

### `std::numbers`

Mathematical constants, correctly rounded, with names: `std::numbers::pi`, `std::numbers::e`, `std::numbers::sqrt2`, `std::numbers::ln2`, and versions for other types such as `std::numbers::pi_v<float>`. They replace hand-typed literals and the non-standard `M_PI`.

### Concepts

A concept is a named requirement on a template parameter (see <Concept id="templates" />). Instead of accepting any type and failing deep inside the function body, a constrained template states what it needs:

```cpp
template <std::floating_point T>
T logisticStep(T N, T r, T K) { return N + r * N * (T{1} - N / K); }

logisticStep(10, 1, 100);   // error: int does not satisfy std::floating_point
```

The error message now names the unmet requirement at the call. You can define your own:

```cpp
template <typename S>
concept ModelState = requires(S a, S b, double h) {
    { a + b } -> std::convertible_to<S>;
    { h * a } -> std::convertible_to<S>;
};

template <ModelState S, typename F>
S eulerStep(const S& s, double h, F rates) { return s + h * rates(s); }
```

A concept checks *types*, not *values*: it can require that a parameter is a floating-point number, but not that it lies between 0 and 1. Value checks still belong in constructors (see <Concept id="constructors" />).

### Designated initialisers

Aggregates, such as parameter structs, can be initialised by naming their members:

```cpp
const Parameters p{.r = 0.9, .K = 400.0, .N0 = 5.0, .years = 12};
```

Two doubles can no longer be swapped by accident, and the code says what each number is. The designators must appear in the order in which the members are declared, and members you leave out take their default member initialisers. Unlike C, C++ does not allow reordering, nesting designators or mixing named and positional values.

### `std::expected`

Some failures are expected and should be handled by the caller rather than thrown as exceptions: a missing value in a parameter file, a line that does not parse. A `std::expected<T, E>` holds either a value of type `T` or an error of type `E`:

```cpp
#include <expected>                                         // C++23

std::expected<double, std::string> parseRate(const std::string& text) {
    try {
        const double r = std::stod(text);
        if (r < 0.0) return std::unexpected("negative rate: " + text);
        return r;
    } catch (const std::exception&) {
        return std::unexpected("not a number: " + text);
    }
}

const auto r = parseRate(field);
if (!r) std::cerr << "error: " << r.error() << '\n';
else std::cout << "rate " << *r << '\n';
```

The error travels with the result, and the caller must unwrap the value before using it, which is the natural moment to check for an error. The table gives the first compiler versions that provide it. Exceptions remain a good choice for errors that should stop the run (see <Concept id="exceptions" />).

### Computing at compile time: `constexpr` and `consteval`

A `constexpr` function can be evaluated by the compiler when its arguments are known at compile time (this already works in C++17). Combined with `static_assert`, it turns some checks on fixed parameters into compile errors:

```cpp
constexpr double netReproductiveRate(double fecundity, double survival) { return fecundity * survival; }
static_assert(netReproductiveRate(2.5, 0.5) > 1.0, "the default parameters must allow growth");
```

C++20 widened what such functions may do: they may use `std::vector` and `std::string` internally, and `consteval` marks a function that must run at compile time. C++23 adds `if consteval`, which lets one function take a different branch when it is being evaluated at compile time. This is useful for lookup tables and fixed derived constants. Do not overdo it: most model parameters come from input files at run time.

### Matrices and grids: `std::mdspan` and `operator[](i, j)`

C++23 adds `std::mdspan` (header `<mdspan>`), a non-owning view that gives a flat block of memory several dimensions. Like a `std::span`, it owns nothing. It suits projection matrices and spatial grids kept in one `std::vector`:

```cpp
#include <mdspan>                                 // C++23
std::vector<double> cells(rows * cols);
std::mdspan grid(cells.data(), rows, cols);       // a rows-by-cols view of the vector
grid[i, j] = 0.5;                                 // multidimensional subscript
```

The multidimensional subscript `m[i, j]` is also new in C++23: a class can define `double& operator[](std::size_t i, std::size_t j)`, so that its own matrix type is indexed the same way. Library support for `<mdspan>` is newer than for the other features in this lesson, so check it before relying on it.

### Small conveniences worth knowing

- `std::erase_if(v, predicate)` removes matching elements from a vector in one call, replacing the erase-remove idiom.
- `map.contains(key)` asks whether a key exists without inserting it, as `operator[]` would.
- Defaulted comparisons: `bool operator==(const State&) const = default;` (see <Concept id="operator-overloading" />).
- `std::views::enumerate` gives an index alongside each element. It needs a standard library from GCC 15 or later; GCC 14 does not have it.

## In biological modelling

The features in this lesson are the baseline of this site, but your own project may have to build with older compilers. Using them is a project decision, not a matter of style. Ask:

- **Where must the model compile?** Your laptop, the cluster, a collaborator's machine, a continuous-integration service. The oldest compiler among them sets the limit. Record the required standard in the build files and the README (see <Concept id="testing-reproducibility" />).
- **Does the feature remove a real risk?** Designated initialisers in parameter structs and `std::format` in output code prevent errors that are easy to make and hard to spot. `std::span` makes function interfaces honest. These are the strongest candidates.
- **Does it make the model easier or harder to read for your collaborators?** A long view pipeline may impress a C++ expert and baffle the ecologist who has to check the model against its description.

A reasonable policy for many projects: write the model in C++23 where the compilers of the whole team support it. If one of them does not, C++20 provides most of the features in this lesson. Only `std::expected`, `std::print`, `std::mdspan` and the C++23 additions to ranges need C++23.

## Common mistakes

- **Using a feature that one target compiler lacks**, and finding out on the cluster. Check the table, and compile with the same flags everywhere.
- **Dangling spans and views.** Neither owns its data; both must not outlive it.
- **Iterating a `filter` view through a const reference.** It does not compile, because the view caches its first match. Pass views by value or by forwarding reference.
- **Expecting concepts to check values.** They constrain types only.
- **Designated initialisers out of order**, or mixed with positional ones.
- **Treating `std::print` as available wherever `std::format` is.** It arrived in C++23, after `std::format`, and needs a newer library; see the table.
- **Rewriting working older code for the sake of it.** Code written in C++17 or earlier remains correct. Modernise where it fixes a problem.

## What C++26 adds

The ISO committee finished the technical work on C++26 in March 2026, and the formal ISO publication follows. GCC 16.1, released on 30 April 2026, has experimental C++26 support, selected with `-std=c++26`. GCC 16 also changed its default language mode from GNU C++17 to GNU C++20, which is one more reason to state the standard explicitly. The examples on this site do not use C++26, and the site's CI does not compile any. The snippets below are labelled C++26 and are not checked.

Several additions matter for models. <Std v="c++26" /> *Contracts* (`pre`, `post` and `contract_assert`) let a function state its conditions in its declaration, which suits the parameter checks that models need. GCC 16.1 includes them as an experimental feature.

```cpp
// C++26. Not compiled by this site's CI.
double logisticStep(double N, double r, double K)
    pre(K > 0.0)
    post(result: result >= 0.0);
```

A related change concerns uninitialised variables: reading an uninitialised local is no longer undefined behaviour but *erroneous behaviour*. The value is defined by the implementation, and compilers may diagnose the read. It is still a bug. The standard library also gains a *hardened* form, which checks preconditions such as a valid index.

<Std v="c++26" /> *Static reflection* lets a program inspect its own types and members at compile time. GCC 16.1 enables it with `-std=c++26 -freflection`. A typical use would be to list the members of a parameter struct without writing the list by hand. The placeholder name `_` marks a value that is deliberately unused.

The new library components <Std v="c++26" /> fit scientific work. `std::simd` provides data-parallel arithmetic, `std::linalg` is a BLAS-style interface for vector and matrix operations, `std::submdspan` takes a slice of an `std::mdspan`, and `std::inplace_vector` is a vector with a fixed capacity and no heap allocation. `std::execution` (senders and receivers) describes asynchronous work.

```cpp
// C++26. Not compiled by this site's CI.
std::inplace_vector<double, 8> stageDensities;   // capacity fixed at 8
const auto [peakYear, _] = findPeak(N);           // `_`: the second value is not used
```

Until all your compilers support these features, keep to C++23.
