## What it is

Many biological data are two-dimensional: seedling counts in a grid of quadrats, the occupancy of patches in a landscape, the transition rates between the stages of a life cycle. C++ has no separate matrix type in its standard library, but the element type of a `std::vector` can be anything, including another vector. A vector whose elements are vectors is a table: each inner vector is one *row*.

```cpp
std::vector<std::vector<int>> seedlings;   // a vector of rows; each row is a vector of int
```

Element `seedlings[i][j]` is read from left to right: `seedlings[i]` is row *i* (itself a vector), and `[j]` picks element *j* of that row. The first index is the row, the second the column, as in the mathematical notation $a_{ij}$.

## Why it matters

Structured populations are where matrices first become indispensable in ecology and evolution. In a matrix population model the state is a vector of stage densities and one time step multiplies it by a projection matrix (see <Concept id="matrix-models" />). Spatial models store a landscape as a grid; distance matrices, contact matrices between age classes and genotype-by-environment tables all have the same shape. Being able to build, fill, traverse and print such a table is the step from one-dimensional trajectories to structured models.

## How it works in C++

### Creating an n × m matrix

The quickest way to make a matrix of `rows` × `cols` zeros uses the fill form of the vector constructor twice:

```cpp
std::vector<std::vector<int>> grid(rows, std::vector<int>(cols, 0));
```

Read from the inside out: `std::vector<int>(cols, 0)` creates a *temporary* row of `cols` zeros, an unnamed object that exists only for this statement. The outer vector is then created with `rows` copies of that row. Each copy is independent, so changing `grid[0][2]` does not touch row 1.

Small matrices with known values can be written out with nested braces, one inner brace pair per row:

```cpp
const std::vector<std::vector<double>> A{
    {0.0, 1.2, 3.0},
    {0.3, 0.4, 0.0},
    {0.0, 0.5, 0.8},
};
```

(The trailing comma after the last row is allowed and keeps the rows uniform.)

Because each row is a vector in its own right, rows can differ in length (a *jagged* array) or be appended with `push_back(row)`. Nothing forces a vector of vectors to be rectangular: that is your responsibility.

### Indexing and nested loops

To visit every element, put a loop over the columns inside a loop over the rows. The outer loop runs once per row; for each row, the inner loop runs over all its columns. `grid.size()` is the number of rows and `grid[i].size()` the length of row *i*:

The order of the loops determines what you can compute on the way. Row totals fall out naturally when the inner loop runs over columns, because each row is completed before the next begins. Column totals need a separate vector of accumulators, one per column, as in the second pair of loops.

Printing a matrix follows the same pattern: print the elements of a row separated by spaces, then a newline at the end of the row, *outside* the inner loop.

## A minimal example

A matrix population model projects the stage densities from one year to the next by a matrix-vector product, $\mathbf{n}(t+1) = \mathbf{A}\,\mathbf{n}(t)$. Element *i* of the new vector is a sum over all stages *j* this year:

$$
n_i(t+1) = \sum_{j=1}^{3} a_{ij}\, n_j(t)
$$

Here $n_j(t)$ is the number of individuals in stage *j* in year *t*, and $a_{ij}$ is the number of stage-*i* individuals produced next year per stage-*j* individual this year (a fecundity in the first row, a survival or transition probability elsewhere). In C++ this is two nested loops and an accumulator. Select a term in the equation or a line in the code to see how they correspond:

<MathCode id="nested-vectors-product" />

The new densities are collected in a separate vector, `next`, which replaces `n` only once all three have been computed. Writing them straight into `n` would let the second and third sums use values that already belong to the next year. The model would then no longer be $\mathbf{A}\,\mathbf{n}(t)$ (see <Concept id="update-order" />).

### Flat storage: one vector, computed indices

A vector of vectors is easy to read but is not one block of memory: each row is a separate allocation. For large grids that are always rectangular, many programmers store all elements in a single vector of `rows * cols` elements, row after row, and compute the position of element (*r*, *c*) as `r * cols + c`:

<Example file="data/matrix_flat_grid.cpp" mark="13,18,27" />

Row *r* starts at element `r * cols`; within the row, the column is the offset. This *row-major* layout is also how image files and numerical libraries store matrices. It guarantees a rectangular shape, keeps neighbouring elements of a row next to each other in memory (good for speed), and is simple to resize or copy. The cost is readability: every access needs the formula, and a slip such as `r * rows + c` produces wrong results without an error. If you choose flat storage, write the formula once, in a small function (see <Concept id="functions" />), rather than at every access.

## In biological modelling

- **Projection matrices.** A Leslie (age-classified) or Lefkovitch (stage-classified) matrix is a small, square vector of vectors. The matrix-vector product above is the whole of one time step; repeated products give the projection, and the long-term growth rate is the dominant eigenvalue of the matrix (<Concept id="power-iteration" />).
- **Landscapes.** Occupancy, habitat quality or density on a grid of patches. Dispersal to neighbouring cells uses indices `[i - 1][j]`, `[i + 1][j]` and so on, which must be checked at the edges of the grid: row −1 does not exist (see <Concept id="indexing-errors" />).
- **Trajectories of structured states.** A vector of stage vectors, one per year, `std::vector<std::vector<double>> history;` with `history.push_back(n);` after every step, is a matrix whose rows are years and whose columns are stages: exactly the table you will want to write to a file.

A name for the type makes such code easier to read. `using Matrix = std::vector<std::vector<double>>;` lets you write `Matrix A(3, std::vector<double>(3, 0.0));` (type aliases are explained in <Concept id="auto-range-for" />).

## Common mistakes

- **Swapping rows and columns.** Decide once whether `[i][j]` means (row, column) or (column, row), write it in a comment next to the declaration, and match the mathematics: in a projection matrix, $a_{ij}$ is the contribution of stage *j* to stage *i*.
- **Using the row count for columns.** `for (j = 0; j < grid.size(); ++j)` runs over as many columns as there are rows. Use `grid[i].size()` for the length of a row.
- **Indexing rows that were never created.** `std::vector<std::vector<int>> g(3);` has three *empty* rows, so `g[0][0]` is out of range. Give each row a size, as in the fill form above.
- **Updating a state in place** during a matrix-vector product, instead of writing into a new vector.
- **Writing `> >`.** Older code (and the course manual) writes `std::vector<std::vector<int> >` with a space; since C++11 the space is unnecessary.
