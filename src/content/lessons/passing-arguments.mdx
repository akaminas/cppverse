## What it is

When a function is called, each parameter is initialised from the corresponding argument. By default the parameter is a **copy**: a new variable that starts with the argument's value but is otherwise unrelated to it. That is *pass by value*. A parameter can instead be declared as a **reference**, written with `&`, and then it is not a new variable at all but another name for the caller's variable: *pass by reference*. A **const reference** combines the two: no copy is made, but the function may only read through it.

## Why it matters

The choice decides what a function can do to the caller's data, and what it costs to call. Passing by value is safe: whatever the function does to its parameters, the caller's variables are untouched. But a function that should update the state of a model, say this year's juveniles and adults, needs to change the caller's variables, and a function that analyses a trajectory of a million values should not copy it on every call. Knowing which mechanism is in play is also essential for reading code: the call `step(juveniles, adults)` looks the same either way.

## How it works in C++

### Pass by value: the parameter is a copy

<Example file="foundations/passing_value_vs_reference.cpp" mark="8-11,21-22" />

`grow_copy` multiplies its parameter `N` by 1.5 and prints 60, yet back in `main`, `N` is still 40. The parameter `N` of `grow_copy` and the variable `N` of `main` share a name, but they are two separate variables in two separate places in memory. The call copies 40 into the parameter; the function changes its copy; the copy is destroyed when the function returns. Step through the [trace below](#explore-it) to watch this happen.

This is C++'s default because it is safe: you can call a function without worrying about what it does to your variables. The consequence is that a function taking only value parameters can pass information back to the caller through one route only, its return value.

### References: another name for the same variable

A *reference* is an alias. Declared with `&` after the type, it must be bound to a variable when it is created, and from then on every use of the reference is a use of that variable:

```cpp
double N = 40.0;
double& population = N;      // population is another name for N
population = 1.5 * population;
std::cout << N << '\n';      // prints 60
```

A reference cannot be re-bound to another variable later, and there is no such thing as a reference to nothing.

As a parameter, a reference makes the function work directly on the caller's variable. In the program above, `grow_in_place` takes `double& N`; nothing is copied, and multiplying `N` inside the function changes `main`'s `N`.

The `&` belongs to the type of the parameter and must appear in every declaration of the function as well as in its definition: the prototype is `void grow_in_place(double& N, double lambda);`. Whether you write `double& N` or `double &N` makes no difference to the compiler; this site attaches the `&` to the type.

Reference parameters let one function update several variables at once, something a single return value cannot do. Here a stage-structured population of juveniles and adults is advanced by one year:

Two details of the function matter.

- **Compute first, then assign.** Both new values are computed from the *old* state into temporary variables before either reference is overwritten. Had the function written `juveniles = fecundity * adults;` first, the adult update on the next line would use the new number of juveniles, silently changing the model. See <Concept id="update-order" />.
- **The call does not show it.** `step(juveniles, adults, 3.0, 0.25, 0.5)` looks exactly like a call by value. Only the declaration of `step` reveals that the first two arguments will be changed. Choose a function name that says so (`step`, `update`, `advance`), and do not use non-const references for parameters that are only read.

A non-const reference must be bound to a variable that can be changed. Calling `grow_in_place(40.0, 1.5)` does not compile: there is no variable for the function to update.

### const references: read without copying

Copying a `double` costs nothing worth mentioning. Copying a `std::vector<double>` with a million elements means allocating 8 MB and copying every value, on every call. A function that only *reads* such an object should receive a reference to it, so that no copy is made. To keep the safety of pass by value, make it a reference to `const`:

### Choosing how to pass

| What the function does with the argument | Pass it as | Example |
|---|---|---|
| reads a cheap value (`int`, `double`, `bool`, `char`) | value | `double next_generation(double N, double lambda)` |
| reads a large object (vector, string, parameter set) | `const&` | `double mean(const std::vector<double>& values)` |
| changes the caller's variable | `&` | `void step(double& juveniles, double& adults, …)` |
| needs a private copy to modify | value | `std::vector<double> sorted_copy(std::vector<double> v)` |
| produces one new result | return it | `double next_generation(…)` rather than an output parameter |

Two remarks on the table. First, returning a value is usually clearer than writing into a reference parameter, even for large objects: returning a `std::vector` from a function does not copy its elements. Use reference parameters when a function must update existing state, or must report several results. Second, passing `int` or `double` by `const&` gains nothing: the reference itself is as large as the value, and reading through it can be slower. Pass cheap types by value.

Finally, keep the order of parameters predictable: the state or main input first, then the parameters that only steer the computation, with any defaulted parameters last (see <Concept id="overloading-defaults" />).

<Callout kind="manual" title="const references for every parameter">
The manual's style guidelines make pass by const reference the default for every parameter, including numbers, and its examples pass `double` and `int` as `const double&` and `const int&`. Modern guidance, followed on this site, passes cheap built-in types by value and reserves `const&` for objects that are expensive to copy. Both are correct C++; the difference is efficiency and readability.
</Callout>

## In biological modelling

- **States updated in place.** A function that advances the state of a model by one step often takes the state by reference: `void step(State& s, const Parameters& p)`. The alternative, `State next(const State& s, const Parameters& p)`, returns a new state and leaves the old one intact, which makes it easy to keep both and is often clearer. Both styles are common; be consistent within a program. See <Concept id="euler" /> for a stepper written in the first style.
- **Parameter sets and data by const reference.** Parameter sets, observed data and stored trajectories are read by many functions and changed by none: pass them as `const&`. Once parameters are grouped into a struct (see <Concept id="structs" />) this becomes the normal way to hand them around.
- **Random-number engines by reference.** A random-number engine has an internal state that each draw advances. Passed by value, the function would draw from a copy, and the next call would repeat the same "random" numbers. Engines are therefore always passed by reference (see <Concept id="random-library" />).
- **Five `double` parameters in a row are a hazard.** In `step(juveniles, adults, 3.0, 0.25, 0.5)` it is easy to swap two survival probabilities without any error from the compiler. Grouping parameters into a named struct removes the risk.

## Common mistakes

- **Expecting a value parameter to change the caller's variable.** It changes a copy. Return the new value, or use a reference.
- **Forgetting the `&` in the prototype or the definition.** The declaration and the definition then describe two different functions, and the linker reports one of them as undefined.
- **Passing large objects by value.** `double mean(std::vector<double> v)` copies the entire vector on every call. Use `const std::vector<double>&`.
- **Non-const references for parameters that are only read.** They mislead the reader and refuse temporaries. Add `const`.
- **Overwriting part of a state before computing the rest.** Compute all new values, then assign.
- **Returning a reference to a local variable.** The local variable is destroyed when the function returns, and the reference refers to nothing; compilers warn about it. Return by value.
