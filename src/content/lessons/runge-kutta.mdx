## What it is

Euler's method uses one slope per step, the one at the start, and pretends it holds for the whole step (see <Concept id="euler" />). Its error comes from the slope changing within the step. Runge–Kutta methods address exactly that: they evaluate the slope at several trial points inside the step and move along a weighted average of those slopes.

### Heun's method

The simplest improvement takes an Euler step as a *trial*, evaluates the slope where that trial step ends, and then moves along the average of the slopes at the start and at the predicted end:

$$
\mathbf{a} = \mathbf{f}(t, \mathbf{x}), \qquad
\mathbf{b} = \mathbf{f}(t + h,\ \mathbf{x} + h\,\mathbf{a}), \qquad
\mathbf{x}(t + h) \approx \mathbf{x} + \frac{h}{2}\,(\mathbf{a} + \mathbf{b}).
$$

Here $\mathbf{x}$ is the state at time $t$, $h$ is the step and $\mathbf{a}$ and $\mathbf{b}$ are vectors of rates (state units per unit time). The trial state $\mathbf{x} + h\mathbf{a}$ is only used to find $\mathbf{b}$; it is never kept. Heun's method needs two evaluations of the right-hand side per step and is *second order*: halving $h$ divides its error by about four instead of two. (Order is defined precisely in <Concept id="numerical-error" />.) When $\mathbf{f}$ depends on $t$ alone, Heun's method reduces to the trapezoidal rule for integrals, which is why it is also called the explicit trapezoidal method.

### Classical fourth-order Runge–Kutta

The method usually meant by "Runge–Kutta" or "RK4" takes four slopes per step: one at the start ($\mathbf{k}_1$), two at the midpoint ($\mathbf{k}_2$ and $\mathbf{k}_3$, each found by a half step along the previous slope), and one at the end ($\mathbf{k}_4$, found by a full step along $\mathbf{k}_3$). It then averages them with weights 1, 2, 2 and 1:

$$
\mathbf{x}(t + h) \approx \mathbf{x} + \frac{h}{6}\bigl(\mathbf{k}_1 + 2\mathbf{k}_2 + 2\mathbf{k}_3 + \mathbf{k}_4\bigr).
$$

Each new slope is computed from a trial state built with the previous one, so the method refines its estimate of the average slope over the step in stages. When $\mathbf{f}$ depends on $t$ alone the two midpoint slopes coincide and RK4 reduces to Simpson's rule, $\tfrac{h}{6}\bigl(f(t) + 4f(t + h/2) + f(t + h)\bigr)$. The full formulas are in the maths–code view below. RK4 is fourth order: halving $h$ divides its error by about sixteen.

## Why it matters

Every integrator faces the same trade-off between speed and accuracy. Smaller steps give smaller errors, but the number of steps, and so the run time, grows like $1/h$. For Euler's method the error is proportional to $h$, so each extra decimal digit of accuracy costs ten times more work. That quickly becomes prohibitive: an answer accurate to six digits might need millions of steps.

The right measure of cost is not the number of steps but the number of times the model's right-hand side is evaluated, because in any realistic model that is where the time goes. Per step:

| Method | Evaluations per step | Order | Error after halving $h$ |
|---|---|---|---|
| Euler | 1 | 1 | ÷ 2 |
| Heun | 2 | 2 | ÷ 4 |
| RK4 | 4 | 4 | ÷ 16 |

RK4 spends four times as much on each step as Euler. But because its error falls so much faster, it can take far larger steps for the same accuracy, and its total cost is usually lower by orders of magnitude. Investing more work per step is cheaper overall. Beyond fourth order the bargain gets worse: a fifth-order method needs at least six evaluations per step, and the number of evaluations keeps outgrowing the order. That is one reason RK4 became the standard fixed-step method.

## How it works in C++

Because Euler's method was written as a stepper with the signature `State(const RightHandSide&, double, const State&, double)`, a Runge–Kutta method is simply another function with the same signature. Heun's method:

```cpp
State heun(const RightHandSide& f, double t, const State& x, double h) {
    const State a = f(t, x);                    // slope at the start
    const State b = f(t + h, axpy(x, h, a));    // slope at the predicted end
    State y(x.size());
    for (std::size_t i = 0; i < x.size(); ++i) y[i] = x[i] + (h / 2.0) * (a[i] + b[i]);
    return y;
}
```

`axpy(x, h, k)` returns $\mathbf{x} + h\mathbf{k}$ component by component. Each slope is a complete vector, computed from a complete trial state, so all variables still move together, just as in Euler's method. RK4 follows the same pattern with four stages; select a term to see its line:

<MathCode id="runge-kutta-rk4" />

Since all steppers share one signature, a pointer to any of them has the type

```cpp
using Stepper = State (*)(const RightHandSide&, double, const State&, double);
```

and the driver can take the method as an argument. Switching from Euler to RK4 changes one word in the call; the model and the driver are untouched. This is the payoff of keeping the model and the method apart.

Two things stand out. First, RK4 wins at every budget, and its lead widens rapidly: going from 40 to 640 evaluations (16 times the work) reduces Euler's error about 23-fold but RK4's about 80,000-fold. Second, Heun is *worse* than Euler at small budgets and only overtakes it at 320 evaluations. A higher order describes how the error behaves *as $h$ becomes small*; with large steps the error is not yet in that regime, and the leading-order prediction can be badly wrong. Order is a promise about small steps, not a ranking at every step size.

## In biological modelling

- **RK4 is the sensible default for fixed steps.** It is easy to implement, works for any smooth model and is accurate enough for most purposes at modest step sizes. Verify every new model by halving the step at least once.
- **Expensive right-hand sides make the argument stronger.** If each evaluation involves a large spatial grid or a sum over many interacting species, the number of evaluations is the run time, and a method that needs fewer of them is the difference between minutes and days.
- **Smoothness matters.** The high order of RK4 assumes that the right-hand side is smooth within each step. A dosing pump that switches on, a seasonal parameter that jumps at the start of winter or a threshold harvest rule puts a kink in the solution, and a step that straddles it loses the accuracy the method promises. Integrate up to the switching time exactly, then restart from there.
- **Higher order is not a substitute for a good model.** RK4 will faithfully reproduce whatever the right-hand side says, including its mistakes. Check the right-hand side first.

## Common mistakes

- **Copy-paste errors in the stages.** Building `k3` from `k1` instead of `k2`, or using `h` where `h / 2.0` belongs, still gives plausible-looking trajectories. Only a convergence test reveals that the order has dropped.
- **Forgetting the time offsets.** The stages are evaluated at $t$, $t + h/2$, $t + h/2$ and $t + h$. For an autonomous model, using $t$ everywhere makes no difference, so the bug survives every test on the logistic equation and appears only when the model becomes seasonal. Test steppers on a non-autonomous problem too.
- **Wrong weights.** The combination is $\tfrac{h}{6}(\mathbf{k}_1 + 2\mathbf{k}_2 + 2\mathbf{k}_3 + \mathbf{k}_4)$. Weights that do not sum to 6 make the method inconsistent: it converges to the wrong answer, or not at all.
- **Comparing methods by step count.** One RK4 step costs four Euler steps. Compare at equal numbers of evaluations, as the example does.
- **Expecting order to help at coarse steps.** The order describes the behaviour as $h \to 0$. With large steps a higher-order method can be worse, as Heun is at the smallest budgets above.

<summary>Answer to exercise 2</summary>

With correct time offsets the RK4 error falls by about $2^4 = 16$ when $h$ is halved. With every stage evaluated at `t`, all four slopes equal $\cos t$ and the step becomes $x + h\cos t$, which is Euler's method. The error now only halves: the method has silently become first order. On the autonomous logistic equation this bug is invisible.
