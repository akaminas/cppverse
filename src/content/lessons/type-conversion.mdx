## What it is

When both operands of `/` are integers, C++ performs **integer division**: the result is an integer and any fraction is discarded. `7 / 2` is 3, and `1 / 2` is 0. The companion operator `%` gives the **remainder** of that division: `7 % 2` is 1.

When the operands have different types, as in `7 / 2.0`, C++ first **converts** one of them so that both have the same type, and then performs the operation in that type. Here the `int` 7 becomes the `double` 7.0, and the result is 3.5.

## Why it matters

In biological models, counts are integers but most derived quantities are not. An allele frequency is a count of alleles divided by a count of alleles; a germination rate is germinated seeds divided by seeds sown; a mean clutch size is eggs divided by nests. Written naively with integer variables, every one of these divisions discards its fraction and usually returns 0. The program compiles, runs and prints a plausible-looking number. This is the single most common transcription error in beginners' models.

Integer division and the remainder are also useful. They convert a running count of days into weeks and days of the week, and keep an index on a ring of habitat patches within range.

## How it works in C++

### Integer division and the remainder

For two integers `a` and `b`, `a / b` is the quotient with the fraction discarded, *rounded toward zero*: `7 / 2` is 3 and `-7 / 2` is −3, not −4. The remainder `a % b` is whatever is left over, so that `(a / b) * b + a % b == a` always holds. Its sign follows the dividend: `7 % 2` is 1 and `-7 % 2` is −1.

<Example file="foundations/division_cycles.cpp" />

Day 45 of an experiment that starts on day 0 is in week 45 / 7 = 6 (counting weeks from 0), and is weekday 45 % 7 = 3 of that week. The same idea gives a season from a month numbered 0 to 11, or the position within a repeating cycle of any length.

For patches arranged in a ring, `(patch + 1) % patches` is the next patch, and it wraps from the last back to 0. For the previous patch, add `patches` before taking the remainder: `(patch + patches - 1) % patches`. Without the addition, the left neighbour of patch 0 would be `-1 % 6`, which is −1, not a valid patch number.

`%` is defined only for integers. For floating-point numbers, `std::fmod` from `<cmath>` computes the remainder (see <Concept id="cmath" />).

<Callout kind="pitfall" title="Division by zero">
Integer division or remainder by zero is undefined behaviour; in practice the program usually stops at once (on Linux, with the confusing message "Floating point exception"). Floating-point division by zero does not stop the program: `1.0 / 0.0` is infinity and `0.0 / 0.0` is "not a number" (NaN), and both then spread silently through every later calculation. Whenever a denominator is a count that can be zero, such as the number of individuals in an empty sample, test it before dividing.
</Callout>

<Callout kind="manual" title="Negative operands">
The manual advises against integer division with negative numbers because compilers used to disagree about the result. Since C++11 the standard fixes it: the quotient is rounded toward zero and the remainder takes the sign of the dividend, on every compiler.
</Callout>

### Conversions, one operation at a time

The arithmetic operators work on two operands of the same type. When the types differ, C++ applies the *usual arithmetic conversions* to bring them together, and it does so separately for each operator, at the moment that operator is evaluated. An expression as a whole has no single type that applies throughout:

```cpp
7 / 2 * 2.0     // (7 / 2) * 2.0  =  3 * 2.0      =  6.0
7 * 2.0 / 2     // (7 * 2.0) / 2  =  14.0 / 2     =  7.0
1 / 2 + 0.5     // (1 / 2) + 0.5  =  0 + 0.5      =  0.5
```

`*` and `/` have the same precedence and are evaluated from left to right (see <Concept id="precedence" />), so in the first line the integer division happens before any `double` appears.

The rules for each operation, in order:

1. **Small integer types are promoted.** `bool`, `char` and `short` are converted to `int` before any arithmetic. `'A' + 1` is the `int` 66, and `true + true` is 2.
2. **If either operand is floating-point, the other is converted to that type**, and if both are floating-point, to the wider of the two (`long double`, then `double`, then `float`). `int` + `double` is a `double`.
3. **If both are integers, the narrower is converted to the wider** (`int` to `long long`, for example). If one is signed and the other unsigned of the same size, the signed one becomes unsigned, with surprising results: `-1 < 1u` is `false`, because −1 becomes a huge unsigned number. `-Wextra` warns about such comparisons.

Converting an integer to a floating-point type keeps its value (exactly, for any `int`). Converting the other way does not.

### Conversion on initialisation and assignment

When a value is stored in a variable, it is converted to the variable's type. From a floating-point type to an integer type, the fraction is discarded, again **toward zero**:

```cpp
int a = 2.9;     // 2
int b = -2.9;    // -2, not -3
```

This is truncation, not rounding. To round to the nearest integer, use `std::lround(2.9)`, which gives 3. (If the value is too large for the integer type, the behaviour is undefined.) Brace initialisation refuses such conversions at compile time: `int a{2.9};` is an error (see <Concept id="initialisation" />).

### Explicit conversion with `static_cast`

`static_cast<double>(n)` produces the value of `n` as a `double`. Applied to one operand of a division, it makes the division a floating-point one:

There are three common ways to avoid integer division, in order of preference:

1. **Give a continuous quantity a floating-point type from the start.** If a variable holds a mass, a rate or a mean, it should be a `double`, and no conversion is needed later.
2. **Convert explicitly with `static_cast`** when integers really are the right type for the counts, as here. The cast is visible and says exactly what happens.
3. **Make the first operation floating-point**, as in `1.0 * allelesA / allelesTotal`. This works because `*` and `/` are evaluated left to right, but it is fragile: `allelesA / allelesTotal * 1.0` is 0 again.

The position of the cast matters. `static_cast<double>(allelesA / allelesTotal)` converts the result of the integer division, which is already 0, into 0.0.

You may also see the older C-style cast `(double)allelesA`. It does the same here, but it can also perform far more dangerous conversions without any visible difference, so modern C++ code uses `static_cast`. Its long, slightly awkward name is deliberate: conversions should be rare and easy to find.

## In biological modelling

Every time a model turns counts into rates, frequencies or means, check the types of the operands. Frequencies of alleles or genotypes, the proportion of infected hosts, the mean number of offspring and survival estimated from marked individuals all start from integer counts.

Conversions in the other direction need as much care. A number of time steps computed from a duration and a step size is a typical case:

```cpp
const double tEnd = 0.3;
const double dt = 0.1;
const int steps = static_cast<int>(tEnd / dt);   // 2, not 3
```

0.3 / 0.1 is not exactly 3 in binary floating-point arithmetic but 2.9999999999999996 (see <Concept id="numeric-limits" />), and the conversion truncates it to 2. The simulation would silently stop one step early. `std::lround(tEnd / dt)` gives 3.

## Common mistakes

- **`int / int` for a proportion.** Convert one operand first.
- **Casting the result** instead of an operand: `static_cast<double>(a / b)`.
- **Relying on order of operations** to make a division floating-point. It works until someone reorders the expression.
- **Negative remainders as indices.** Add the cycle length before taking `%`.
- **Truncating when you mean to round.** Converting to `int` drops the fraction toward zero; use `std::lround`.
- **Comparing signed with unsigned integers.** Heed the warning; the comparison may convert −1 into a very large number.
- **Dividing by a count that can be zero.**
