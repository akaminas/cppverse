## What it is

A `std::vector` is a sequence of values of one type, kept under one name. A vector of `double` can hold the population size in every generation of a simulation; a vector of `int` can hold the number of nests in each of forty plots. You reach an element by its position, called its *index*, and the vector can grow or shrink while the program runs.

Three properties define it:

- **One element type.** A `std::vector<double>` holds only `double`s. The type goes between angle brackets.
- **Contiguous storage.** The elements sit next to each other in memory, in order. That is why jumping straight to element 30 is as fast as reading element 0.
- **Resizable.** Elements can be appended at the end at any time. The vector manages its own memory, so you never allocate or free anything by hand.

## Why it matters

A model with one variable, such as the size of a single population, can live in a single `double`. As soon as you want to keep the *history* of that variable, or describe many things at once (stages, patches, individuals, replicate runs), you need a container. Without one you would have to declare `N0`, `N1`, `N2`… by hand and could not decide at run time how many generations to simulate.

The vector is the container you will use most. A trajectory is a vector; the state of a stage-structured population is a vector; a population of individuals in an individual-based model is a vector of individuals. Other containers exist (see <Concept id="container-choice" />), but the vector should be your default.

## How it works in C++

The vector lives in the header `<vector>`. Its full name, `std::vector<double>`, is read "vector of double": `std::vector` is a *class template* (a type with a blank for the element type), and `<double>` fills the blank. <Concept id="templates" /> explains the mechanism later; for now, the angle brackets simply name the element type.

### Creating a vector

There are four everyday ways to create one:

```cpp
std::vector<double> N;                    // empty: no elements yet
std::vector<int> nests(40);               // 40 elements, each 0
std::vector<double> survival(3, 0.85);    // 3 elements, each 0.85
std::vector<int> clutchSizes{4, 6, 5, 3}; // exactly these four values
```

Round parentheses give a *size* (and optionally a fill value); curly braces give the *values* themselves. The difference matters: `std::vector<int> a(3)` has three zeros, whereas `std::vector<int> b{3}` has a single element whose value is 3.

A vector can also be created as a copy of another, `std::vector<int> original = clutchSizes;`. The copy is independent: changing one does not change the other.

<Callout kind="manual" title="Sized vectors are filled with zeros">
The manual says that the elements of `std::vector<int> v(15)` are left uninitialised. That is not the case: a vector created with only a size *value-initialises* its elements, so numbers start at 0 (and `bool`s at `false`). You can rely on `std::vector<double> births(n)` being all zeros. The manual also writes nested types as `std::vector< std::vector<int> >` with a space between the closing brackets; since C++11 `>>` works without the space.
</Callout>

### Indexing: from 0 to size() − 1

`N[t]` is the element with index `t`. Indices start at **0**, so a vector of five elements has the indices 0, 1, 2, 3 and 4. The last index is always `N.size() - 1`. An indexed element can be read or written like any variable:

```cpp
nests[2] = 7;                  // write: the third plot has 7 nests
double now = survival[1];      // read the second element
```

`N.size()` returns the number of elements. Its type is `std::size_t`, an *unsigned* integer type (it cannot hold negative numbers), large enough for the size of any object. Loop counters that are compared with `size()` should be `std::size_t` as well. Comparing an `int` with a `std::size_t` mixes signed and unsigned types and makes the compiler warn, with good reason (see [Bounds and off-by-one errors](#bounds) below).

### Member functions

A vector is an *object*: besides its elements it has functions of its own, called with a dot after the vector's name. The ones you will use constantly:

| Call | Effect |
|---|---|
| `v.push_back(x)` | append `x` at the end; the size grows by one |
| `v.pop_back()` | remove the last element; the size shrinks by one |
| `v.front()`, `v.back()` | the first and the last element (can be read or assigned to) |
| `v.size()` | the number of elements, as `std::size_t` |
| `v.empty()` | `true` if there are no elements |
| `v.clear()` | remove all elements |
| `v.at(i)` | element `i`, with a check that `i` is a valid index |

`front`, `back` and `pop_back` require at least one element. Calling them on an empty vector is an error the program does not detect, so test `empty()` first when the vector might be empty.

The loop near the end of that program, `for (int clutch : clutchSizes)`, is a *range-based for loop*. It reads "for each element `clutch` of `clutchSizes`", visiting every element once, in order, without an index. Use it whenever you need each element but not its position. ### Bounds and off-by-one errors

Every index you use must lie between 0 and `size() - 1`. Time loops make this easy to get wrong, because a model run over *T* steps has *T* + 1 states (the initial one plus one per step), and anything computed *between* states (changes, growth rates) has only *T* values.

The square-bracket operator does **not** check the index. Reading `N[N.size()]`, one past the end, is *undefined behaviour*: the program may print a nonsense number, crash, or appear to work and fail later, and the compiler is allowed to assume it never happens. Writing out of range is worse, because it can silently overwrite other data in your program. Nothing in the language stops you.

`.at(i)` does the same as `[i]` but checks the index first. If the index is invalid it *throws an exception* of type `std::out_of_range`: the normal flow of the program stops, and unless the exception is caught the program ends with an error message rather than continuing with wrong numbers. The `try { … } catch (…) { … }` block catches the exception so that the program can say what happened; <Concept id="exceptions" /> explains exceptions properly. Without it, the program would stop at the bad index with a message from the C++ runtime.

Two habits prevent most of these errors:

- Write loop conditions that count *elements*, not positions: `t < N.size()` visits every element; `t + 1 < N.size()` visits every element that has a successor.
- Never compute `N.size() - 1` on a vector that might be empty. Because `size()` is unsigned, `0 - 1` does not give −1 but wraps around to the largest possible `std::size_t` (about 1.8 × 10¹⁹ on a 64-bit machine), and a loop up to that value runs off the end at once. `t + 1 < N.size()` has no such problem.

<Callout kind="tip" title="When to use .at()">
`.at()` costs one comparison per access. In inner loops of large simulations, `[]` with indices that are correct by construction (a loop from 0 to `size()`) is the norm. Use `.at()` where an index comes from outside the loop's control: user input, a file, or a computed position such as `t + lag`. While developing, you can also ask the standard library to check every `[]`: GCC's libstdc++ does this when you compile with `-D_GLIBCXX_ASSERTIONS`.
</Callout>

## In biological modelling

Almost every simulation on this site stores something in a vector:

- **Trajectories.** One element per time step, as in the program above. Reserve index 0 for the initial state, so that `N[t]` is the state at time *t* and the code matches the notation $N_t$ of the model.
- **Structured states.** The densities of juveniles, subadults and adults in a stage-structured model form a vector *n*(*t*); a matrix model multiplies it by a projection matrix (<Concept id="nested-vectors" />, <Concept id="matrix-models" />).
- **Populations of individuals.** In an individual-based model each element describes one individual (<Concept id="individual-representation" />).
- **Replicates and parameter sweeps.** The final population size of each replicate run, or one result per parameter value, collected for later summary.

Two practical points follow. If you know in advance how many values you will store, create the vector with that size, `std::vector<double> N(T + 1)`, and assign `N[t + 1] = …` inside the loop; this is equivalent to `push_back` but avoids repeated growth (see <Concept id="container-choice" />). And keep the units and the meaning of the index in a comment next to the declaration: `// N[t]: females per hectare in year t`.

## Common mistakes

- **Starting at 1.** The first element is `v[0]`. A loop `for (std::size_t i = 1; i <= v.size(); ++i)` skips the first element and reads one past the last.
- **Confusing `(n)` and `{n}`.** `std::vector<double> x(5)` has five zeros; `std::vector<double> x{5}` has one element, 5.0.
- **Indexing an empty vector.** `std::vector<double> N; N[0] = 40.0;` writes to an element that does not exist. Use `push_back`, or create the vector with a size first.
- **`front()`, `back()` or `pop_back()` on an empty vector.** Undefined behaviour, not a run-time error message. Test `empty()` first.
- **Mixing signed and unsigned indices.** `for (int i = 0; i < v.size(); ++i)` compiles with a warning. Use `std::size_t` or a range-for.

<summary>Answer to exercise 3</summary>
`v` starts as {5, 5}; `v.size()` is 2, so after the `push_back` it holds {5, 5, 2}. The value pushed is a `std::size_t` converted to `int`. With `-Wall -Wextra` this particular conversion is usually silent, but `-Wconversion` warns that an unsigned value is being narrowed to a signed type. Writing `v.push_back(static_cast<int>(v.size()))` makes the conversion explicit.
