## What it is

A **weighted lottery** chooses one of $n$ options, numbered $0, 1, \dots, n - 1$, where option $i$ has a weight $w_i \ge 0$ and is chosen with probability

$$
P(i) = \frac{w_i}{W}, \qquad W = \sum_{j=0}^{n-1} w_j .
$$

The weights need not add up to one; only their relative sizes matter. Egg counts, fecundities, encounter rates and event rates can all be used as weights directly. An option with weight zero is never chosen.

## Why it matters

Weighted choices appear wherever individuals or events differ in how likely they are.

- **Reproduction.** In a population model, the parent of each offspring is chosen in proportion to fecundity or fitness.
- **Which event happens next.** In a stochastic simulation with several possible events, the next event is chosen in proportion to its rate. This is step 4 of <Concept id="gillespie" />.
- **Behaviour.** A forager picks a patch in proportion to its attractiveness; a predator meets prey types in proportion to their encounter rates.

## How it works in C++

### `std::discrete_distribution`

`<random>` provides the weighted lottery as `std::discrete_distribution`. Called with an engine, it returns an index. You can give it the weights in two ways.

For a short, fixed list, write them in braces, as an *initializer list*:

```cpp
std::discrete_distribution<int> nestSite{1.0, 3.0};  // P(0) = 0.25, P(1) = 0.75
```

When the weights are in a `std::vector`, pass the *range* of the vector, its `begin()` and `end()`:

```cpp
const std::vector<double> eggs{12.0, 30.0, 0.0, 8.0, 20.0};
std::discrete_distribution<std::size_t> pickMother(eggs.begin(), eggs.end());
const std::size_t mother = pickMother(rng);   // 0, 1, 3 or 4; never 2
```

`eggs.begin()` and `eggs.end()` are *iterators*: markers for positions in the vector. `begin()` marks the first element and `end()` the position *just past* the last one. Together they describe the half-open range of all elements, and the distribution reads every weight from `begin()` up to, but not including, `end()`. Many standard-library functions take a range this way; <Concept id="iterators" /> explains iterators in full. The distribution *copies* the weights: changing the vector later does not change the distribution.

The template argument is the type of the index returned. `std::size_t` is convenient when the index is used to look up an element of a vector, because it is the type that `.size()` returns.

### How the lottery is drawn

The algorithm behind a weighted lottery is short. Lay the weights end to end on a line from 0 to $W$, so that option $i$ owns an interval as wide as its weight. The interval ends are the *cumulative sums*

$$
C_i = \sum_{j=0}^{i} w_j, \qquad \text{option } i \text{ owns } [\,C_{i-1},\, C_i\,), \quad C_{-1} = 0 .
$$

Draw $u$ uniformly from $[0, 1)$ and choose the option whose interval contains $u W$. Because $uW$ is uniform on $[0, W)$, it lands in an interval of width $w_i$ with probability $w_i / W$, which is exactly $P(i)$. The program below implements this with a linear scan, using fixed values of $u$ instead of random ones so that you can check each line by hand.

Two details are worth seeing in the trace. A zero weight gives an empty interval, $[42, 42)$, so no value of $u$ can select female 2. And the intervals are *half-open*: a target of exactly 42 belongs to the next non-empty interval, female 3's, not to female 1's.

A linear scan costs time proportional to $n$ for every draw. `std::discrete_distribution` does better when you draw many times from the same weights: standard libraries typically compute the cumulative sums once, when the distribution is constructed, and then find the interval by binary search. Construct the distribution once and reuse it while the weights stay the same; build a new one when they change.

### Zero, all-zero and missing weights

- **A zero weight** is allowed and means "never".
- **All weights zero** is not allowed. The standard requires the total $W$ to be positive; with $W = 0$ there is no probability to normalise, and the result is undefined. In a model this usually means that nothing can happen any more (every patch is empty, the population is extinct), and the program should detect it and act on it.
- **No weights at all** is defined, but surprising: an empty range is treated as a single weight of 1, so the distribution always returns 0, as if a population with no members had an individual 0.
- **Negative, infinite or NaN weights** violate the preconditions.

So check before you draw:

```cpp
double total = 0.0;
for (const double w : weights) total += w;
if (weights.empty() || total <= 0.0) {
    // No option can be chosen. Handle it explicitly: for example, record
    // that the population is extinct and stop the simulation.
}
```

## In biological modelling

### Neutral drift by multinomial sampling

The Wright–Fisher model is the simplest model of genetic drift. A haploid population has a constant size of $N$ individuals and non-overlapping generations. Each individual of the next generation copies the allele of a parent chosen at random from the current generation. With $n_i$ carriers of allele $i$, the parent carries allele $i$ with probability $n_i / N$: a weighted lottery with the allele counts as weights. Repeating the lottery $N$ times gives the counts of the next generation, a draw from a **multinomial distribution**.

The program follows five alleles, A to E, that are equally common at first and confer no advantage. It reports when an allele is lost and when one is fixed.

<Example file="stochastic/neutral_drift_alleles.cpp" mark="30-32,41" />

Run it with several seeds. The order in which alleles are lost, and the generation of fixation, change from run to run; that *some* allele is fixed does not. The distribution is rebuilt every generation because the weights, the counts, change. The new counts go into a separate vector `next`, and only replace `count` once all $N$ offspring have been drawn.

A useful summary of diversity is the **heterozygosity** $H = 1 - \sum_i p_i^2$, where $p_i = n_i / N$: the probability that two individuals drawn at random (with replacement) carry different alleles. For the Wright–Fisher model one can show that, on average over replicate populations,

$$
\mathbb{E}[H_{t+1}] = \Big(1 - \frac{1}{N}\Big) H_t, \qquad \text{so} \qquad \mathbb{E}[H_t] = H_0 \Big(1 - \frac{1}{N}\Big)^{t},
$$

with $t$ in generations. The figure compares this prediction with simulated populations built from the same weighted lottery.

<Figure id="weighted-lottery-drift" />

Any single population loses heterozygosity in irregular steps and reaches $H = 0$ at fixation; only the mean over many populations follows the smooth curve. The simulated mean lies within its sampling error of the exact expectation, a direct check that the lottery assigns parents in the right proportions.

Two extensions are common. *Selection* enters by multiplying each count by the allele's relative fitness before it is used as a weight. And for large $N$ with few alleles, drawing $N$ separate parents is wasteful: the same multinomial counts can be obtained from a short chain of binomial draws, one per allele (exercise 3).

### Choosing which event happens

In a continuous-time stochastic model the weights are the rates of the possible events, called propensities, and the lottery decides which event happens next: an infection or a recovery, a birth or a death. Because the rates change after every event, the distribution is rebuilt each time, which costs about as much as a linear scan. That is the subject of <Concept id="gillespie" />.

## Common mistakes

- **All-zero or empty weights.** Check the total before drawing; treat a zero total as a state of the model.
- **Forgetting to rebuild.** The distribution keeps a copy of the weights. If the weights change, construct a new distribution (or set new parameters with `param()`).
- **Overwriting the weights while drawing.** In a hand-written lottery that reads `count` directly, updating `count` during the same generation changes the probabilities for the remaining offspring. Collect the new counts in a separate vector.
- **Mismatched order.** Weight $i$ must belong to option $i$. Keep weights in the same container order as the individuals or events they describe.
- **Normalising by hand.** Dividing weights by their total is unnecessary, and with integer weights it can truncate them to zero.

<details>
<summary>Worked answer to exercise 2</summary>

Compute $H$ from the counts with a short function:

```cpp
double heterozygosity(const std::vector<int>& count, int N) {
    double sumSquares = 0.0;
    for (const int n : count) {
        const double p = static_cast<double>(n) / N;
        sumSquares += p * p;
    }
    return 1.0 - sumSquares;
}
```

With five equally common alleles, $H_0 = 1 - 5 \times 0.2^2 = 0.8$, and with $N = 25$ the expectation after 20 generations is $0.8 \times 0.96^{20} \approx 0.35$. The replicate means should be within a few hundredths of the expectation; the figure above shows the same comparison for 400 replicates.
</details>
